Isolation.

This VBR server also protects VMware and Nutanix. The orchestrator only ever changes jobs it created itself. Everything listed on this page is read so that new jobs avoid its names and start times, and is never modified.

How that is enforced

  • Only jobs whose description carries the [hvbo ...] or [hvbo-copy ...] marker are owned. The marker is written when the orchestrator creates a job.
  • Before anything is sent, every operation is checked against the list of owned job IDs taken at plan time. One failure refuses the whole batch.
  • On the VBR server, every change re-reads the live job and refuses it unless it carries the marker and is a Hyper-V backup job.
  • New jobs are only created under names no other job on the server uses.
  • No job is ever deleted, started, stopped or disabled. No global or server setting is changed. The only change cmdlets used are listed alongside, and an automated test fails if any other one appears.

Change cmdlets the orchestrator may run

  • Add-VBRHvBackupJob, Add-VBRBackupCopyJob: new jobs only
  • Add-VBRHvJobObject, Remove-VBRJobObject: VMs in owned jobs
  • Set-VBRJobOptions, Set-VBRJobVssOptions: owned jobs, at creation
  • Set-VBRJobSchedule, Enable-VBRJobSchedule: owned jobs
  • Move-VBRBackup: restore points between two owned jobs
